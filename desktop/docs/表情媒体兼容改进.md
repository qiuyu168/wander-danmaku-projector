# GIF 与新版 QQ 表情兼容改进

2026-11-13。此前“图片未加载”可能来自下载超时、8 MiB 文件限制、GIF 超过 120 帧或总解码预算、无下载地址、失效 URL、动态 WebP 或损坏文件；同一个占位文字无法区分原因，不能断言每个失败 GIF 都来自同一原因。

本次改进：

- 图片准备最多等待 2.5 秒（原为 1 秒），下载限时 6 秒（原为 3 秒）；文字仍独立准备，不被慢图片阻塞。轨道准备完成后最多等待 500 ms，队列总量上限保持 50。
- 多图消息超时时保留已完成的图片，只替换尚未完成部分；不在上屏后临时扩张图片布局。
- GIF 超过动画预算时尝试静态首帧，避免整图拒绝。保留 8 MiB、1600 万像素、帧边界校验；超过 2000 帧仍拒绝。静态降级计入媒体诊断 `staticFallbacks`。
- GIF 数据子块截断和帧矩形越界会明确拒绝，避免损坏帧越界解码。
- QQ face 由 0～39 扩展为 275 个已知编号映射，覆盖部分新版表情至 348。映射参考本机 NapCat 自带 QFace 元数据（QSid/EMCode），图片仍从腾讯 `qzonestyle.gtimg.cn` 下载，没有打包第三方图片。未列出的 ID 不猜测映射。
- 后台支持 `mface`，并在 image/mface 有合法十六进制 `emoji_id` 且缺 URL 时，按当前 NapCat 的腾讯商城资源格式构造 HTTPS 地址。原 URL 优先，仍经过客户端官方域名与图片边界校验。
- 媒体诊断增加最近错误原因 `lastError`（不含完整下载 URL），便于区分 HTTP、格式、超时等问题。

实际验证：类型检查与 12 项单元测试通过；Electron 解码验证 121 帧 GIF 返回有效静态首帧；官方 CDN 表情 14、300、348 下载和解码通过。协议测试补充 mface 的 URL 构造验证。

限制：新版 QQ 超级表情、随机结果/互动动画不一定能复原为 QQ 中的效果；官方旧素材可能显示静态或不同尺寸版本。动态 WebP 尚未支持；不自动放开文件大小限制，不关闭 TLS 校验。要诊断仍失败的具体表情，请记录“06 聚合与媒体诊断”的 `lastError` 并提供对应样例类型；普通 Unicode emoji 仍由系统字体渲染。
