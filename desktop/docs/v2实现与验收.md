# wander 0.2.0：实现、协议与验收

日期：2026-11-12（北京时间）。需求依据：工程根目录 `wander_功能改进开发指导_v2.md`。本版实现前三项，未修改第四项复制/扩展显示策略。

## 实现概况

| 功能 | 实现 |
| --- | --- |
| 加群二维码 | 主进程选择静态图片、验证并复制；按群保存标题/多行说明、四角位置、宽度、边距；独立透明穿透窗口展示 |
| 紧急隐藏 | 弹幕和展示卡一并隐藏；仅显示卡片时快捷键仍可隐藏；切群/拔屏/睡眠/退出清理卡片 |
| 图文弹幕 | OneBot 有序段 → 兼容 WS → 受控媒体下载 → 文字/图片混合块；高图片占两条轨道 |
| GIF | omggif 解码首帧并用 pngjs 编码 PNG；动画保留原 GIF，同屏数量超限或关闭动画时用首帧 |
| 聚合 | 同群内容键、固定匹配窗口、上屏更新 ×N、上游消息 ID 重投去重；原始消息数与实体数分开 |
| 互动 | 跨越 66/100 等阈值一次触发，最高等级优先，固定几何边界；并发最多 2 个，支持减少动态 |
| 配置 | schema 1 自动迁移至 2，保留旧来源/屏幕/样式，新配置填默认；迁移前保留 v1 副本 |

控制面板保留用户已修改的首页文案。新增代码集中于 `renderer/improvements.tsx`、`shared/aggregation.ts`、`main/media.ts`、`main/image-header.ts`；`renderer/card.ts` 是独立二维码窗口，`renderer/overlay.ts` 管理统一布局及计数。

## 图文协议与降级

原 `text/color/size/sender/trace` 字段保留。增加可选 `segments`：

```json
{
  "text": "欢迎 [图片][QQ 表情]",
  "segments": [
    {"type":"text","text":"欢迎 "},
    {"type":"image","mediaId":"QQ稳定文件标识","url":"https://gchat.qpic.cn/...","alt":"[图片]"},
    {"type":"face","faceId":"14","alt":"[QQ 表情]"}
  ]
}
```

`mediaId` 不是本地路径或可直接下载的资源 ID。Rust 保留 QQ 文件标识及临时 URL；透明层只能通过受限 IPC 请求主进程媒体模块，不能直接加载该 URL。主进程缓存按完整下载 URL 的 SHA-256 管理；内容聚合按 `mediaId`，签名 URL 刷新但文件标识相同时仍可聚合。无稳定标识时用完整 URL，宁可少合并，不误合并不同图片。旧网页会显示兼容摘要，不负责新图片渲染。

OneBot 要求 `messagePostFormat=array`，现有模板已是该配置。旧 CQ 字符串仍走原文字转换，媒体优先使用结构化数组。第一版实际适配范围：

- PNG/JPEG/静态 WebP、GIF。GIF 只在允许动画且未达到上限时播放。
- QQ face 0～39 使用官方旧版表情素材映射（0/14 等特殊编号做映射）；其他 face/特殊超级表情显示替代文字。QQ 新版素材或网络不可用时也可能降级，不能声明所有表情都能还原。
- 一条最多 16 段、3 张图片；纯图片有效。文字长度与屏蔽规则检查真实文本段，媒体不绕过过滤。
- 缺少可下载 URL 的图片有替代描述；动态 WebP、视频、文件和语音尚不支持。

## 媒体和资源边界

图片只允许 QQ 官方图片域名的 HTTPS，包括 qpic.cn、qq.com、gtimg.cn 及 multimedia.nt.qq.com.cn；旧 `http://gchat.qpic.cn` 升级到 HTTPS 再请求。逐次检查重定向和 DNS 私网结果；不关闭证书校验，使用 Electron 网络栈以兼容系统网络设置。无法从 QQ 官方可读地址取得的本地容器文件不作为任意文件读取开放。

每图 8 MiB、最多 1600 万像素；下载并发 4，排队最多 50 个、排队等待 1.5 秒、单次下载总限时 3 秒。渲染侧只等待 1 秒媒体准备，之后降级；后台下载可完成并缓存供后续使用。GIF 额外限制最多 120 帧、逻辑面积乘帧数不超过 3200 万像素。缓存按估算字符串占用 LRU 淘汰，总额 200 MiB。先读文件头检查分配规模，再解码；坏文件/超限/不支持格式降级。

二维码静态文件导入限 10 MiB，保存到 `%APPDATA%/wander/join-cards/<sha256>.png`；配置只保存资源 ID。图片不打包进分发文件。移除卡片会移除配置引用；旧图片暂保留在本机目录，未做用户资源自动删除，避免误删。可在程序退出且确认不再使用后手动清理未引用文件，后续可增加资源清理界面。

## 聚合与队列的精确定义

聚合窗口从第一条消息到达起计，默认 10 秒；屏上实体离开、等待实体过期/溢出、清空或切群后不复活。第一条不等窗口结束。文本首尾空白/换行规范化后精确匹配，图文段顺序参与键；不同发送者相同内容合并。固定宽度徽章避免计数增长时碰撞。

媒体准备和轨道等待独立：纯文字立即准备，媒体最多等 1 秒后用已就绪内容或替代文本；每个实体准备完成后最多等 500 ms 分配轨道，重复输入不重置任何期限。等待及媒体准备实体合计最多 50 个；爆满丢最旧实体，记录其代表的原始消息条数。准备中的慢图片不占用文字队首。

`received` 是验证格式后的原始接收，`created` 是创建实体，`merged` 是更新实体的重复输入，`retried` 是上游 ID 重投；`shown` 是开始显示实体，`represented` 是已在屏代表的原始消息。丢弃记录 `expired/overflow` 实体数和 `droppedMessages` 原始条数。隐藏/暂停期间忽略另计。媒体、缓存、特效统计单列。

原服务按内容去重会吞掉计数，启用聚合后通过“启动 / 连接服务”定向将 `DANMAKU_DEDUP_WINDOW` 设为 -1，并备份原 .env。过滤词和长度限制不变；原始上游传输丢失无法由聚合补回。

66 级为局部渐变文字，100 级增加徽章柔光；阈值配置为排序不重复的 2～9999 整数，最多 8 个。同次跨多个阈值只播放最高级，最多并发 2 个；超限和减少动态时仅静态强调。计数上限显示 9999+，不移动/放大碰撞边界、不延长滚动生命周期。

## 自动验证与设备边界

已建立参数/迁移、聚合键/期限、消息 ID、阈值跨越、图片分配限制的单元测试；协议集成验证文字兼容、图文顺序、纯图片、文本屏蔽、群隔离。GUI 检查包含二维码副本、用户文字、切群/隐藏联动、101 条重复占一轨道、66/100 效果和图片块。

部分运行时 Windows 返回 `Current display surface not available for capture`。该次真实面板截图不可用，会写入 `captureWarnings`；布局可另用静态离屏副本检查，离屏截图**不证明** HDMI 合成、鼠标实际穿透或真实显示帧率。截图文件名 `*-layout.png` 明确区分用途。

当前检测到 LQ156T1JW05，1707×960 DIP、150% 缩放；窗口 API 四舍五入后为 1708×240 DIP。与旧版性能报告中的 G52 Max/125% 条件不同，不做跨设备直接前后比较。

## 最终验证结果

2026-11-12 完成 TypeScript 检查、10 项单元测试、Docker 后端协议集成测试及 0.2.0 便携包 GUI 验证。GUI 验证覆盖二维码复制与自定义文字、切群/隐藏联动、101 条重复消息合并为一个轨道、66/100 特效边界、图文混排、双帧 GIF、动画上限及 QQ 官方表情 CDN 实际下载。最终运行没有截图警告。测试通过本机后端合成消息，没有向 QQ 群发送消息。

压力测试原始记录见 [benchmark-v2.json](benchmark-v2.json)。同一电脑、同一后端对照原网页和新客户端，顶部 25%、40 DIP 字号、144 DIP/秒、20 字符文本。分阶段输入共 810 条：常规 300 条（每秒 1 条，持续 5 分钟）、不同内容突发 200 条（每秒 20 条）、恢复 10 条、相同内容 100 条和 80% 重复内容 200 条。

| 指标 | 结果与解释 |
| --- | --- |
| 常规阶段新客户端 | 收到 300 条，显示 250 条，50 条等待轨道过期；显示完整率 83.3%，尚未达到常规消息全部显示的目标 |
| 常规阶段软件延迟 | 已显示消息从接收 WS 到软件可见的近似 p50 为 3.1 ms、p95 为 5.7 ms、p99 为 8.9 ms；同条件原网页 p95 为 51.5 ms |
| 全程合并与容量 | 收到 810 条，显示 280 个实体，合并 257 次，代表原始消息 537 条；丢弃过期消息 273 条，队列溢出 0，结束时待处理队列 0 |
| 突发等待 | 已显示消息的轨道等待接近 500 ms 上限；不同内容大量涌入会丢弃过期消息，防止堆叠和延迟不断增长 |

上述延迟不是 QQ 发送到 HDMI 出光的端到端延迟，也不包含校园网及 QQ 上游等待。常规阶段漏显说明顶部五轨道、当前字号/速度与固定计数徽章仍有容量限制；可减小字号或提高速度改善，不能声称容量目标已经全部达标。后续应优先优化轨道调度与徽章预留宽度，在防碰撞前提下提高显示完整率。

阶段切换时状态采样可能包含下一阶段首条消息，因此不使用各阶段快照差推导精确显示率；全程统计等待收尾后取值。聚合后一个实体代表多条原始消息，应看 `represented` 而非只看 `shown`。软件观察器对重复文字的采样也不等同于徽章每次更新。原网页会重叠显示，其显示数量不能直接代表可读性。

当前系统的 Ctrl+Alt+D 已被其他程序占用，客户端会保留提示并允许继续保存其他设置；请在面板更换组合，或使用托盘隐藏。没有擅自替换用户快捷键。测试结束后恢复原有用户配置。

真实 QQ 图片消息的完整兼容、投影手机扫码、PPT、HDMI、1 小时连续运行仍须实机验收，不能用合成输入替代。特殊 QQ 超级表情与动态 WebP 尚不支持；媒体不可用时显示替代文字。
