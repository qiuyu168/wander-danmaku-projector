# 架构与协议

> 本文保留 0.1.0 架构基线。0.2.0 的图片消息段、二维码独立窗口、配置迁移和聚合调度，以 [v2实现与验收.md](v2实现与验收.md) 为准。

## 数据路径

`QQ → NapCat → OneBot 反向 WS :5099/onebot → Rust 过滤/广播 → :5098/danmaku/<group> → overlay renderer`

Electron 主进程管理窗口、屏幕、托盘、快捷键、配置、Docker；Preact 控制面板通过受限 preload IPC 控制主进程。透明窗口直接订阅 Rust；不通过面板转发真实弹幕，面板预览只用本地文字。

模块：`src/main/index.ts` 为窗口/生命周期，`runtime.ts` 为项目服务管理；`renderer/control.tsx` 是设置界面，`renderer/overlay.ts` 是独立渲染器，`shared/queue.ts` 提供有界新鲜队列；`smoke.ts`、`benchmark.ts` 为显式测试入口。

两个窗口关闭 Node 集成、启用沙箱及上下文隔离、拒绝新窗口和外部导航。主进程检查 IPC 来源及参数，Docker 通过参数数组调用。QQ 文本通过 `textContent` 输出。诊断接口只在 5099 内网，Compose 未映射该端口。

## 窗口与绘制

目标显示器使用 Electron DIP `bounds`；区域高度为 `round(bounds.height * topRatio)`，默认 25%。无边框透明、不可聚焦、鼠标穿透、跳过任务栏、`showInactive()` 显示并置顶。不设置整个窗口不透明度，只有文字使用 opacity。

轨道按文字高度排列，发射时检查前方间隔与追尾条件，禁止重叠凑数字。文字从右侧立即开始进入视口。每帧只更新 transform，退出后删除 DOM；在屏最多 200 个元素、等待最多 50 条、每条等待最多 500 ms。无任务时暂停 rAF；投屏窗口关闭后台节流。

隐藏、切群、重连、重定位、睡眠会清队列。切群使用 generation 标记，旧连接的迟到回调不再接收。目标屏拔出即隐藏；重接后由用户选择和开始，避免覆盖主屏。ID 和辅助屏幕信息均保存，但不猜测新 ID 是否为原设备。

## 下游兼容协议 v1

保留原字段，增加可选 `trace` 对象，旧网页仍可消费：

```json
{
  "text": "示例弹幕",
  "color": null,
  "size": null,
  "sender": "示例发送者",
  "trace": {
    "id": "account-messageId 或 本次采集时间-序号",
    "serverReceivedAtMs": 1794450000000,
    "serverProcessingMs": 0.12,
    "sourceTimestampSec": null
  }
}
```

`serverProcessingMs` 使用 Rust 同一进程 `Instant`，包括处理和中间件等待，不含 QQ 网络、广播后等待及显示硬件。`serverReceivedAtMs` 为解析过程中记录的 epoch 关联时间，与完整文本帧到达有微小偏差；不用于证明毫秒级端到端指标。OneBot 有 message ID 时保留账号关联 ID；无 ID 使用时间和单调序号。`sourceTimestampSec` 仅保存上游秒时间，无值时为 null。

`GET :5098/health` 只返回健康与协议版本；`GET :5099/status` 返回 OneBot 活跃连接/QQ 在线信息、过滤计数、处理耗时统计。主进程通过项目容器内部读取私有接口，不把管理接口暴露到局域网。QQ 状态来自当前连接事件/心跳，90 秒无事件视为失活；不是历史日志匹配。界面每 4 秒刷新，不能当作毫秒级掉线检测。

后端保留长度、屏蔽词、可选去重；丢弃空白/无文字消息，完整正文日志降为 debug。慢下游发送超过 2 秒断开并单独统计广播滞后，防止慢客户端拖累。原 ring/broadcast 容量仍为 32；前置 ring 溢出当前库不能精确计数，是服务诊断的已知盲区。

## 配置、迁移和运行数据

品牌更新后首次启动会复制旧 `%APPDATA%/元火弹幕投屏/settings.json` 到 `%APPDATA%/wander/settings.json`；原文件保留。界面颜色来源及名称更新范围见 [界面配色](界面配色.md)。

设置放在 Electron `userData/settings.json`，Windows 默认 `%APPDATA%/wander/settings.json`；schemaVersion=1，共享验证器校验范围，临时文件加原子替换保存。损坏文件备份成 `.invalid-时间`；未支持的版本同样备份并回退默认值，不尝试静默猜测字段。`lowLatency` 暂为保留字段，第一版始终采用低延迟队列。

第一次从原服务 `.env` 和 `napcat/.deploy.json` 导入账号/群号，仅是填写输入框，不代表账号已登录。日常启动不调用原 `start.ps1`，不覆写 Compose；只定向更新 `ACCOUNT` 和对应账号的 OneBot 连接，旧文件备份 `.bak`。

QQ 会话仍在服务目录 `napcat/`；二维码短暂复制到系统临时目录，面板到期隐藏，不进入便携包或导出。独立分发只按 allowlist 复制服务源文件，生成空账号 `.env`。依赖锁在 package-lock.json，Electron 45.3.1、Preact 11.2.0、TypeScript 7.0.2、esbuild 0.28.2；本机 Node 24.11.1。当前 NapCat 镜像摘要记于验收记录；Compose 仍沿用 existing latest，本版普通启动不拉取新镜像。

## 更新与回滚

桌面源代码修改后 `npm.cmd run check`、`npm.cmd test`、`npm.cmd run package`；后端修改后单独重建本项目服务镜像。不要在服务启动按钮中默认添加 `--build` 或清理全局 Docker。

不使用桌面程序时退出客户端，原网页 `http://localhost:5098/<群号>` 继续可用，无需回滚服务。原后端二进制备份在本机 `D:/DanmakuRuntime/danmaku-server-before-desktop`；升级后的服务镜像也标记为 `danmaku-server-desktop:0.1.0`。需要真正回滚后端时应使用备份源/镜像重建，保留 napcat 数据和 `.env`，不要删除 Docker 数据。修改账号配置需要恢复时先停止本项目服务，将相应 `.bak` 恢复后再启动。二进制备份不包含运行时，不能直接在 Windows 执行 Linux ELF。
