# wander 0.3.0 升级与验收

日期：2026-11-15。此版本实现现场测试反馈的七项更新，保留 schema 2，旧配置缺少的 `aggregation.startCount` 自动补 6；旧动画上限保留，可在面板提高，新配置默认 8、最大 16。

## 消息与连接

OneBot 模板开启 `reportSelfMessage`，后端接受 `message` 和 `message_sent`，保留消息 ID 去重，登录账号从手机或其他 QQ 客户端发的群消息也能作为弹幕。本程序不新增向 QQ 群主动发送消息的接口。

@ 优先用事件自带名称，否则通过现有反向 WS 的只读 `get_group_member_info` API 查群名片，再回退昵称；全体成员有专门文案。查询总并发 4、每次 650 ms 限时、缓存 10 分钟（含失败缓存），缓存最多 2048 项。查不到时显示“@群成员”，不再显示 QQ 号。首次查询可能增加少量延迟，不阻塞心跳和其他消息；单消息总查询预算约 650 ms，多个 @ 超出预算会降级。

日常启动复用现有 QQ 容器，只有账号变化或 OneBot 配置确有变化时才需要重启/替换 QQ。客户端会识别现有 Compose 的工作目录，避免原工程/便携包切换改变 QQ 数据目录。更新弹幕后台仅替换服务容器，不拉取或重建 QQ 镜像。刷新登录先检查最新状态，已在线不刷新，两次主动刷新至少间隔 2 分钟。

OneBot 心跳模板改为 15 秒，超过 90 秒无任何消息会关闭该 WS 连接，交给 NapCat 重连，不自动重启 QQ 或反复扫码。掉线时提示先在手机处理安全认证。不能保证腾讯账号永不断线或不触发风控，也没有绕过安全认证。当前检查旧 QQ 容器重启数 0、OOMKilled=false，不能把用户遇到的认证直接归因于 OOM；新部署内存上限为 2 GiB，已有容器普通启动不会仅为这项配置被强制重建。

## GIF 与布局

媒体下载最大 32 MiB，12 秒传输超时；投屏图片准备最多等 6 秒，普通文字不等待图片。多图超时保留已完成部分。下载总并发仍为 4，GIF 优化并发最多 2，队列和内存缓存有界。

大 GIF 在 worker_threads 中解码与缩小，最长边约 320 像素；帧数较多时进一步缩小，保证输出像素预算不超过 2400 万。重编码为 256 色，保留透明、帧延时与 disposal=2/3 合成语义。可动画的源工作量限 2.4 亿像素、最多 600 帧；超出转静态首帧，超过原有硬边界（尺寸、2000 帧、损坏数据等）拒绝。转换可能降低画质，不能把所有格式和无限尺寸放开。

同屏动画可选最高 16，超出仍用首帧；轨道高度和防碰撞也限制实际数量。“更多动画”不保证任何设备都能高帧率运行。测试采用本地生成动画，不发 QQ。

## 屏幕与聚合

显示器新增、移除、尺寸/DPI 变化统一延迟 600 ms 合并处理。保持显隐状态，依次选择原 ID、唯一名称尺寸匹配、可用外屏、主屏，保留原偏好以便重连回原屏。二维码卡跟随。不主动解除用户隐藏，首次开始投屏仍需明确操作。仅一块物理屏幕时，自动选屏算法可测试，但不能代替 HDMI 实测。

聚合默认同内容第 6 条且拥挤时才开始；拥挤定义为存在等待实体，或活动实体达到可用文本轨道数的约 60%（至少 2）。前面的独立弹幕继续滚动，不追溯消失；后续合并到仍活着的同内容实体，×N 只表示本实体代表条数。新增计数徽章前检查后方碰撞空间，无法安全加宽时不合并。第一条不再预留空计数徽章，空闲时能显示更多文本。默认匹配窗 10 秒，固定期限，不因重复输入延长；长度/关键词/过载限制继续生效。

## 国内安装与增量包

完整目录 `release/wander-0.3.0` 提供官方 Docker、WSL 安装器及本版本预构建服务 TAR。安装器官方 Authenticode 签名均已实机验证，另附 SHA-256，安装时双重检查。不把来源不明的第三方 EXE 称为“国内源”。首次安装不再默认调用 winget 或 wsl --update 从境外下载。

缺少 NapCat 镜像时从 `docker.m.daocloud.io` 下载后标记为 Compose 使用的原名称；已有镜像不重复拉取。手动构建使用 DaoCloud 基础镜像、USTC Alpine、npmmirror npm、rsproxy Cargo。未写入全局 Docker daemon 配置，不关闭 TLS，不能保证国内镜像长期无故障。

`release/wander-update-0.3.0` 是增量包，含“升级旧版.bat”、校验清单、应用/后台文件及 0.3.0 服务镜像，不含 Docker、WSL、Electron。目标旧版须为本项目 Electron 45.3.1。升级先退出客户端，脚本备份替换文件，跳过 `.env`、`napcat`、用户设置和二维码，识别正在用的服务目录，导入镜像并启动后台。第一次开启自身消息上报会重启一次 QQ 接入。

备份保存在旧目录 `upgrade-backup-时间`，原配置另有 `.pre-030.bak`。回退需先退出客户端，恢复备份中的程序及后台文件，再重新构建旧后台镜像或使用仍在 Docker 的旧镜像；不能只恢复新版本 Compose 名称而声称已回退。升级包有校验和但未提供发布者签名，应从可信来源获取。

## 验证记录

- TypeScript 检查、14 项单元测试通过，包含旧配置迁移、选屏匹配与回退、重复计数固定窗口、屏蔽词和图片边界。
- 在隔离 Docker 容器用真实 WS 验证自身消息、@ API 请求响应及缓存、@全体成员、图文与 mface 兼容、群隔离和原过滤；没有向 QQ 发消息。
- Electron 媒体测试通过：121 帧 GIF 保持动画、800×600 缩小为 320×240 动画、9 MiB 下载及官方 QQ 14/300/348 表情解码。
- 增量脚本只读验证和文件升级夹具通过，原 `.env` 和模拟 QQ 会话原样保留；本机实际升级完成后 QQ 已恢复在线。用户 APPDATA 由测试隔离配置保护。
- 打包版 GUI 联动通过：101 条输入保留 4 条独立弹幕与 ×97 聚合条、计数边界不重叠；8 个 GIF 同时动画，动画上限为 1 时其余用首帧；二维码、关键词热更新、切群隔离、66/100 特效回归均通过。最终截图警告为 0。Windows 截图工具增加超时，避免不可用显示表面让测试无限等待。
- 长期账号稳定性、手机安全认证与 HDMI 插拔仍需用户实测，不能由合成消息和单屏算法测试替代。全新 Windows 上安装 Docker/WSL 的管理员与重启全过程尚未实测；安装脚本语法、只读环境检查和安装器签名/哈希检查已通过。
