# wander 弹幕姬 0.3.0：安装与使用说明

## 从旧版升级（无需重装依赖）

老用户使用 `desktop\release\wander-update-0.3.0` 增量包：先完整解压，从旧客户端系统托盘退出，再双击包内 **升级旧版.bat**，选择原来包含 `electron.exe` 的 `wander` 文件夹，保持 Docker 运行。无需复制整套新客户端或重新下载 Docker、Electron、NapCat。

升级会校验文件、备份被替换的程序，导入随包后台镜像，并复用当前部署目录。账号、QQ 数据、屏蔽词、样式和二维码保留。首次开启“登录账号自身消息上报”需要重启一次 QQ 接入，若手机要求认证，请本人完成。之后普通启动不会反复重启 QQ。升级失败可修复提示的问题后重跑，不要删除 QQ 数据。

新电脑请用 `desktop\release\wander-0.3.0` **完整包**，含官方签名的 Docker、WSL 安装程序及弹幕服务镜像；它比增量包大。完整包的首次安装优先使用本地安装文件，NapCat 镜像通过 DaoCloud 国内镜像源获取。手动重新构建时使用 DaoCloud、USTC、npmmirror、rsproxy，不修改系统全局 Docker 配置，不关闭证书验证。镜像服务可能变化或暂不可用，不能保证任何国内源永久可用。

wander 将指定 QQ 群的消息显示为桌面顶部滚动弹幕，适用于校园活动、讲座、晚会、PPT 和视频互动。客户端采用北京林业大学绿色系配色，支持透明置顶、鼠标穿透，无需 OBS。

当前提供 Windows x64 便携版。“便携”指客户端免安装，QQ 接入和弹幕后台仍依赖 Docker Desktop。本说明介绍换电脑、首次部署及活动现场操作。

## 1. 功能一览

| 功能 | 说明 |
| --- | --- |
| QQ 群消息投屏 | 接收指定群的消息，登录 QQ 必须已加入该群 |
| 自身消息与 @ 名称 | 登录账号自己发的群消息也上屏；@ 优先群名片，其次昵称，查询不可用时显示“群成员” |
| 选择显示器 | 可选主屏或第二屏；顶部区域默认 25%，可调 10%～50% |
| 透明置顶、鼠标穿透 | 弹幕覆盖在桌面上方，点击可穿过弹幕操作下面的程序 |
| 弹幕样式 | 统一颜色或随机柔亮配色，调整字体、字号、速度、透明度、阴影 |
| 入群二维码展示卡 | 导入图片，按群保存自定义标题、说明、位置、尺寸和边距 |
| 图片与表情包 | 图文混排，支持 PNG、JPEG、静态 WebP、GIF，以及部分 QQ 表情 |
| 重复聚合 | 默认同内容达到 6 条且画面拥挤时才合并为大号 `×N`，默认匹配窗口为 10 秒 |
| 互动特效 | 默认 66、100 层触发炫彩，可调整阈值、关闭特效或减少动态 |
| 过载保护 | 限制排队数量和时间，避免无限积压；高峰可能丢弃部分消息 |
| 屏蔽关键词 | 每行一个词，包含任意关键词即整条屏蔽，活动中保存即可生效 |
| 现场控制 | 清空、暂停新弹幕、显示/隐藏、全局快捷键、系统托盘 |
| 测试与诊断 | 本地测试文字、图片、66/100 效果，不向 QQ 群发消息 |

## 2. 换电脑需要带什么

### 必须：整个便携目录

新电脑请使用 `desktop\release\wander-0.3.0` 完整包，将整个文件夹压缩成 ZIP，复制到新电脑后完整解压；解压后可将文件夹改名为 `wander`。旧版目录完成增量升级后可以继续在原电脑使用，但增量包不附带大型离线安装器，因此首次部署另一台电脑应使用完整包。目录结构大致如下，未列出的文件也要全部保留：

```text
wander\
├─ 首次安装.bat           ← 新电脑先运行这个
├─ installer\             ← 安装脚本，必须保留
├─ 启动弹幕投屏.bat       ← 新电脑使用这个入口
├─ electron.exe
├─ DLL、PAK 等运行文件
├─ locales\
├─ resources\
│  ├─ app\                ← 已构建的客户端
│  └─ server\             ← 后台源码、构建文件和初始配置
├─ docs\
├─ README.md、使用说明.md
└─ 版本信息.json、许可证等
```

**不能只复制 EXE，不要删 DLL、locales 或 resources。** 新电脑不需要源码工程、原始项目 ZIP、`node_modules`，也不用安装 Node.js、npm 或 Rust。

工程根目录的“启动弹幕投屏客户端.bat”用于这台开发电脑复用原后台，不是独立分发入口。换电脑请用便携目录内的“启动弹幕投屏.bat”。

0.3.0 完整包提供 Docker/WSL 官方安装程序和弹幕后台镜像；不包含当前电脑的 QQ 登录会话、个人设置、群二维码或聊天数据。新电脑运行首次安装准备环境，填写账号并扫码。NapCat 镜像仍需国内源下载，也可自行携带。增量升级包仅用于已安装的旧电脑。

### 可选：迁移屏蔽词、样式和二维码

先从系统托盘退出客户端，在 Windows 地址栏输入 `%APPDATA%\wander`，单独备份：

```text
settings.json
join-cards\
```

新电脑先打开一次客户端，再从托盘退出，把两项复制到新电脑相同的 `%APPDATA%\wander` 目录。如已有设置，先备份再覆盖。重新打开后，**重新选择新电脑的显示器**，核对账号和群号，再保存。

设置与二维码目录一起带，才能保留展示卡。`settings.json` 含账号和群号，应作为个人配置保管。备份设置不等于迁移 QQ 登录状态，新电脑仍可能需要扫码。也可以不带这些文件，从头配置。

无需复制原工程的 `napcat` 登录数据，推荐在新电脑重新扫码，不要把个人 QQ 会话放进公开分发包。

## 3. 新电脑安装环境

### 推荐：首次安装入口

将整个 `wander` 文件夹解压到普通可写目录，双击 **首次安装.bat**：

1. 自动检查系统、目录完整性、硬件虚拟化与已有 Docker。
2. 需要时弹出管理员授权，启用 WSL 和虚拟机平台。如果提示必须重启，保存工作并重启，**重启后再次双击“首次安装.bat”继续**。
3. 缺少环境时使用随包 `installers` 中的 WSL MSI、Docker EXE，校验官方数字签名及 SHA-256 后安装，不再依赖 winget 境外下载。Docker 首次界面确认和系统授权仍需本人操作。
4. 等待 Docker Linux 引擎，导入包内可选的 `wander-images.tar`，或下载并构建缺失的后台镜像。
5. 完成后打开客户端，填写 QQ 和群号，点击“启动 / 连接服务”，扫码并选择投屏屏幕。

**不是“点击一次，最后统一重启就全部完成”**：可能需要中途重启并重新运行安装入口，已有环境的电脑则可能不必重启。脚本不会强制重启，也不能代办扫码、BIOS 操作和首次使用界面的确认。

如果提示缺少安装程序，请完整复制新版完整包；增量包不提供新电脑的环境安装文件。BIOS 未开启虚拟化、校园网阻断下载等情况会提示处理，不绕过系统限制或关闭证书校验。镜像准备时间取决于网络和电脑性能。

可重复运行，不覆盖已有账号与客户端设置。失败时显示日志路径，日志位于临时目录，名为 `wander-install-日期时间.log`。脚本只准备镜像，不提前启动未配置账号的 QQ 容器。已有后台镜像默认复用，升级请在客户端点击“构建 / 更新服务”。

日常使用仍双击 **启动弹幕投屏.bat**，无需每次首次安装。以下保留手动流程，自动安装受阻时可参考。

### 手动安装环境

1. 准备能运行 Docker Desktop 的 Windows x64 电脑，建议 Windows 11。内存建议至少 8 GB，同时运行 PPT/视频时建议 16 GB；为 Docker、镜像及构建缓存预留约 10～20 GB 空间，实际可能更多。
2. 从 [Docker Desktop 官网](https://www.docker.com/products/docker-desktop/) 安装 Windows 版。根据安装提示启用 WSL 2、虚拟化及相关系统组件，按提示重启。系统版本须满足所安装 Docker Desktop 的当前要求。
3. 打开 Docker Desktop，完成首次初始化，使用 **Linux containers**，等待引擎运行。
4. 将便携包完整解压到普通可写目录，例如 `D:\wander`。不要直接在 ZIP 里运行，也不要放在需要管理员权限才能写入的目录。
5. 准备稳定网络，首次需要下载 Docker 镜像及构建依赖。建议活动前完成部署，不要临到开场才构建。

如果提示 WSL 缺失或版本过旧，按 Docker 提示操作，必要时在管理员 PowerShell 使用 `wsl --install` 或 `wsl --update`，然后按提示重启。无需在宿主 Windows 安装 Rust 和前端开发工具。

## 4. 首次运行和 QQ 登录

1. 打开 Docker Desktop，等待引擎就绪。
2. 双击便携目录中的 **启动弹幕投屏.bat**。
3. 在“01 消息来源”填写 QQ 账号和目标 QQ 群号，点击底部 **保存并应用**。该 QQ 必须已经加入目标群。
4. 如果“首次安装.bat”已准备好镜像，点击 **启动 / 连接服务**。如果没有使用自动安装，展开 **连接诊断与延迟统计**，点击 **构建 / 更新服务**。等待下载、编译与容器启动完成；首次可能较久，不要反复点击。
5. 点击 **显示登录二维码**，用手机 QQ 扫码并确认。过期后点击 **刷新登录**，稍等再显示。QQ 已在线时无需重新扫码。
6. 确认本地服务运行、QQ 在线、OneBot 已连接。订阅接通不等于 QQ 已登录。

首次部署完成后，日常只需打开 Docker，再点击 **启动 / 连接服务**，不必每次构建。容器有自动重启设置，Docker 引擎启动后服务也可能已经运行。

同一电脑不要同时运行原工程和另一份独立便携部署：当前使用固定容器名 `danmaku-server`、`danmaku-napcat` 和主机端口 `5098`，会冲突。

## 5. HDMI 投屏和样式

推荐用 **扩展屏幕**：

1. HDMI 连接投影或第二屏，按 **Win+P → 扩展**。
2. 把 PPT/视频放到第二屏，主屏保留控制面板。
3. 在“02 投影显示器”选择目标屏，顶部区域默认约 25%，点击 **保存并应用**。
4. 点击 **在所选屏幕定位区域** 核对位置，再点击 **开始投屏**。
5. 在“03 弹幕样式”点击 **在投影上测试**，再请群成员发消息验证真实接入。

在“03”调整颜色、字体、字号、速度、透明度与阴影，保存后新弹幕使用新样式；在屏文字通常保留创建时样式。消息太密时，可减小字号、提高速度或适当扩大区域。

**复制投屏**会让两块屏幕显示相同画面，弹幕也会出现在两边。鼠标穿透能让你操作下面的程序，但视觉上仍有遮挡；当前没有“复制模式只在副屏出现弹幕”的功能。

投屏进行中切换分辨率、复制/扩展或拔插屏幕，会自动重新定位并保持投屏开启。优先原屏幕 ID，再匹配名称与尺寸；原屏缺失时选可用外屏，否则选主屏，原屏恢复时优先切回。无需再次开始投屏。弹幕可能因此暂时出现在主屏，随时用紧急隐藏停止；二维码卡也跟随位置调整。首次使用仍需点击开始，主动隐藏后不会因插屏自行开启。活动前请实际验证 HDMI、PPT 全屏和鼠标穿透。

## 6. 入群二维码展示卡

1. 从 QQ 保存目标群的加群二维码图片，传到电脑。
2. 填好目标群号，在“04 入群展示卡”点击 **导入 / 更换二维码图片**。
3. 填写自定义标题与说明，设置位置、宽度和边距。
4. 点击 **显示到投屏**；只导入不会自动展示。可单独点击 **隐藏展示卡**。

图片导入时会复制，移动原图不影响展示。设置按群保存，清空弹幕会保留卡片；切群、紧急隐藏、目标屏断开及退出会隐藏它。

这里是 **加群二维码**，不是“01”的 **QQ 登录二维码**。请用手机实际扫描投影上的图，确认群号、清晰度和有效期；二维码有效性与入群审批由 QQ 决定。

## 7. 图片、表情包和 GIF

2026-11-13 兼容改进：较长或解码预算较大的 GIF 会尽量以静态首帧显示；图片最多准备 2.5 秒，多图中已完成的资源不会因另一张超时全部降级。新增 275 个已知 QQ 表情编号映射及商城表情解析，特殊互动效果仍不保证原样复现。媒体诊断提供最近失败原因和静态降级次数。

在“05 表情包与图文弹幕”开关图片和动画，设置同屏 GIF 上限（最高 16）。新配置默认 8 个，旧配置保留原值，升级后可手动调高并保存。可点击 **在投影上测试图文**。

单文件下载上限提高到 32 MiB，图片准备最多 6 秒（文字消息不等待它）。较大 GIF 在独立线程缩小到最长边约 320 像素后播放，减少主线程阻塞及显存压力；颜色会量化，细节可能减少。最多处理 600 帧、总源像素工作量 2.4 亿；超预算仍尽量显示静态首帧，损坏文件和超大尺寸会拒绝。存在轨道和同屏动画数量限制，不能保证所有大型 GIF 都完整播放。

- 普通 PNG、JPEG、静态 WebP、GIF 按原消息顺序与文字共同滚动，一条最多 3 张图片，图片块最多占两条轨道高度。
- 动画超过上限时用静态首帧。部分 QQ 常用表情已适配，特殊/未知表情可能显示替代文字。
- 动态 WebP、视频、语音和文件暂不支持。
- 需要从 QQ 官方地址下载图片，网络不通、链接失效、没有地址或超时会降级。首次冷缓存也可能降级，不能保证所有 QQ 表情包原样显示。

## 8. 重复聚合和互动效果

“06 重复聚合与互动”中可设置开始合并条数，默认 6 条、匹配窗口 10 秒。同内容先独立滚动，达到数量且轨道开始拥挤时，才合并后续消息；空闲时继续独立显示。已上屏的独立弹幕不突然消失，×N 只统计该聚合条代表的消息，避免重复计数。标点或图片不同不会强行合并，合并不延长滚动时间，已离屏的弹幕不复活。

默认 **66** 层触发炫彩文字，**100** 层增强效果。可以修改阈值、关闭特效或选择减少动态效果。本地预览和投影测试都不会发消息到 QQ。

开启聚合后，点击一次 **启动 / 连接服务**，客户端会关闭旧后台的按内容去重选项，避免重复消息在到达前被丢弃。

过载保护限制队列和等待时间。大量不同消息涌入时会丢弃过期消息，不能保证每条都显示；顶部 25%、较大字号下，常规长消息也可能因无空轨道过期。可查看合并、过期、溢出及媒体失败统计，调整字号、速度或显示区域。

## 9. 屏蔽关键词

“07 屏蔽关键词”中 **一行填一个词**，点击底部 **保存并应用** 即刻生效，无需重启服务。包含任意关键词的消息整条屏蔽；已经上屏、排队中和等待图片的匹配消息也会移除。可在活动前预设，活动中随时追加。

- 所有群共用，重启后保留；清空列表并保存即可取消屏蔽。
- 按字面包含匹配，英文不区分大小写，全角英文也可匹配，不执行正则。
- 最多 500 个词，每词最多 80 字。过于常见的单字会误伤正常消息。
- 检查图文消息的文字，不识别图片里的字，也不保证识别谐音、插字等变体。
- 只影响本客户端投屏，不撤回 QQ 群消息，也不控制旧网页。

面板显示本次连接拦截的新消息数量。新规则移除历史弹幕时，不追溯扣减累计显示统计。

## 10. 活动现场控制

| 操作 | 效果 |
| --- | --- |
| 保存并应用 | 保存设置；屏蔽词立即生效 |
| 清空 | 清除弹幕和队列，后续消息正常显示，保留二维码卡 |
| 暂停新弹幕 | 在屏文字继续滚动，新消息丢弃，恢复不补播 |
| 立即隐藏 | 隐藏弹幕和二维码卡，清掉队列，隐藏期间不积压 |
| Ctrl+Alt+D | 默认全局显示/隐藏，可在面板更换组合 |
| 关闭面板 | 收进托盘，双击托盘图标重新打开 |
| 退出客户端（保留服务） | 从托盘或诊断区退出桌面程序，后台继续运行 |
| 停止本项目服务 | 在诊断区停止 QQ 与弹幕容器，再退出客户端 |

快捷键被占用时请改组合并保存，或使用托盘隐藏。客户端启动后弹幕默认隐藏，需要明确点击开始。

## 11. 常见问题

**没有 Docker / Docker 未运行**：先安装并打开 Docker Desktop，等待 Linux 引擎就绪。Docker 安装在自定义位置时，确认终端能执行 `docker --version`，必要时重启客户端。

**首次构建下载失败 / 校园网证书错误**：完成校园网认证，确认镜像源与构建依赖可访问。网络使用组织签发证书时，按组织要求配置 Windows 和 Docker 的受信证书，不要关闭 TLS 验证。客户端不会自动改全局 Docker 配置。可换稳定网络完成首次部署。

**服务运行但没有消息**：检查 QQ 在线、OneBot 连接、已入群、群号正确；再检查显示器、开始投屏、暂停状态和关键词。先用本地测试区分显示问题与 QQ 接入问题。

**登录码看不到或已过期**：等待后台启动；刷新登录后稍等再显示。QQ 已在线无需扫码，手机要求二次验证时按 QQ 提示处理。

“等待登录 / 状态未确认”不一定是 WSL 未运行：QQ 未扫码前 OneBot 尚未连接时也可能出现。先点击“显示登录二维码”；“刷新登录”会重启 QQ 后台，等待新二维码后自动展示，最多等待约 90 秒。等待时按钮暂不可用；超时请检查网络和启动日志。Docker Linux 引擎已运行时，无需另外手动打开 WSL 终端。

**消息少了**：可能被关键词、后台原有过滤、15 秒陈旧消息保护或过载策略丢弃。保持电脑时间同步，查看诊断；可减小字号或提高速度。软件延迟统计不代表手机发送至 HDMI 显示的完整延迟。

**表情包变成文字**：可能格式不支持、特殊 QQ 表情、下载失败或准备超时。检查“05”开关及媒体诊断。

**QQ 掉线并提示安全认证**：先在手机 QQ 完成腾讯要求的认证，保持原登录数据、网络与设备稳定，不连续扫码、不清空 QQ 数据。程序不会为掉线自动循环重启 QQ。OneBot 传输断开会由 NapCat 重连；确需手动刷新登录时，至少间隔 2 分钟。第三方 QQ 接入不能承诺永不断线或免风控，当前没有绕过认证的功能。

**容器名或端口冲突**：先停掉另一套部署；新版会优先复用已部署项目的后台目录，避免误换数据路径，但不要并行运行两套客户端管理同一后台。

**找不到服务目录**：检查是否复制整个便携目录，并从包内脚本启动。普通用户无需设置 `DANMAKU_PROJECT_DIR`；若曾设置过，确认它指向有效后台目录。

**弹出“选择包含 docker-compose.yml 的弹幕服务目录”**：应选择文件夹，不是 YAML 文件。独立便携版选择 `wander\resources\server`；这台开发电脑若要沿用原有 QQ 登录与后台数据，选择工程中的 `danmaku-server-master\danmaku-server-master`，或取消后使用工程根目录“启动弹幕投屏客户端.bat”。目录须同时包含 `Cargo.toml` 与 `docker-compose.yml`。这两种入口使用的后台数据目录不同，不要同时部署；独立目录可能需要重新扫码。本次已修正便携版自动识别，应能直接找到随包 `resources\server`；旧包出现此提示时可按以上方法选择。

**打包报 DLL 的 EPERM**：开发电脑先从托盘退出客户端，单纯关闭面板仍驻留后台，再重新打包。不必删除 DLL。

## 12. 可选：携带已有 Docker 镜像

普通换电脑按前面的联网构建流程即可。目标电脑下载不方便时，可以额外导出原电脑现有镜像，缩短首次准备时间；这不包含 QQ 登录会话。

在原电脑 Docker 运行时执行（本工程当前镜像名已经核对）：

```powershell
docker save -o wander-images.tar wander-server:0.3.0 mlikiowa/napcat-docker:latest
```

等待导出完成，把 TAR 与便携包一起带到新电脑。新电脑先安装并启动 Docker，再执行：

```powershell
docker load -i .\wander-images.tar
```

随后打开客户端，填写账号群号，点击 **启动 / 连接服务** 使用导入镜像。这条路线首次不点“构建 / 更新服务”，否则会重新构建。之后需要升级后台时再联网构建。

镜像名不一致时，用 `docker inspect danmaku-server --format '{{.Config.Image}}'` 核对原电脑的实际名称；不要带不支持图片协议的旧后台。目标架构也必须兼容。

新版已随包提供 `wander-server-0.3.0.tar`，无需自行构建弹幕后台。上面导出法用于额外携带 NapCat，不能替代 QQ 登录所需网络。首次安装优先导入新版服务 TAR；若还需导入额外 NapCat 镜像，可先手动执行 `docker load`。

## 13. 开发者入口与验证记录

只运行便携包无需开发环境。修改源码时，在工程 `desktop` 中使用 Node.js 24：

```powershell
npm.cmd ci
npm.cmd run check
npm.cmd test
npm.cmd start
# 从托盘退出便携客户端后再打包
npm.cmd run package
```

输出为 `desktop\release\wander`。如果设置过 `ELECTRON_RUN_AS_NODE`，启动 Electron 前清除此环境变量。首次下载 Electron 运行时也需要网络。

开发细节和验证记录见随包 `docs`：`v021屏蔽词与计数.md`、`v2实现与验收.md`。工程内对应路径为 `desktop\docs`。现场 HDMI、PPT 全屏、实际扫码和真实 QQ 图片兼容性仍需活动前实测。
